# Модуль «Оргструктура предприятия» — доведение до целевого вида

Базовый модуль уже собран ранее и работает на реальных данных: импорт штатной расстановки (мастер из 6 шагов), версии DRAFT/ACTIVE/ARCHIVED с публикацией и откатом, снимки подразделений/должностей/назначений, связь с рабочими центрами, публичная страница `/structure` с визуальной схемой `OrgGraph`, внутренний раздел `/org-structure` и админ-вкладки `/admin/org`. Новых справочников и таблиц не создаём — доводим то, что есть, до требований.

## Что будет сделано

### 1. Одна схема во всех разделах
Внутренний раздел сотрудника и админ-вкладка «Схема» переводятся на тот же визуальный компонент, что уже используется на публичной странице (вместо старого спискового варианта с 7 режимами). Разница только в правах: внутри видны ФИО, руководители и переходы в карточку сотрудника, публично — только подразделения, должности и численность.

### 2. Навигация и управление схемой
К существующим зуму, перемещению полотна, поиску, полноэкранному режиму и раскрытию веток добавляются:
- «Развернуть всё» / «Свернуть всё»;
- breadcrumb-навигация по выбранной ветке с возможностью «сфокусироваться» на подразделении (drill-down по клику);
- по умолчанию раскрыты 2 уровня;
- поиск расширяется на ФИО сотрудников и должности (сейчас поиск по ФИО работает только там, где данные о людях доступны — внутри платформы);
- мобильный режим: пошаговый drill-down с теми же крошками, без горизонтальной прокрутки.

### 3. Карточка подразделения и сотрудники
Карточка показывает название, тип подразделения ровно как в исходных данных, руководителя (если определён), численность и число вложенных подразделений, кнопку +/−. В боковой панели — должности и (для авторизованных с правами) список сотрудников; клик по сотруднику ведёт в его существующий профиль. Никакие подразделения, типы и уровни не придумываются — только то, что пришло из файла.

### 4. Производственная ветка
Для подразделений, связанных с рабочими центрами (существующая связь «подразделение ↔ рабочий центр»), в панели деталей появляется блок: рабочие центры → профессии → сотрудники, на существующих сущностях проекта, без дублей.

### 5. Валидация импорта
Существующий отчёт валидации (ошибки/предупреждения/«требует проверки») дополняется явными проверками: дубли идентификаторов, отсутствующий родитель, циклическая подчинённость, подразделение без места в дереве, сотрудник без должности или подразделения. Ошибки блокируют публикацию и показываются администратору; иерархия автоматически не «домысливается». После публикации новой версии схема перестраивается автоматически.

### 6. Экспорт текущего представления
К существующим Excel/PNG/печати добавляется SVG, а PNG/PDF начинают учитывать текущее состояние: выбранную ветку (фокус) и фактический уровень раскрытия, а не всё дерево целиком.

### 7. Документация
В актуальный MD-обзор проекта добавляется раздел про модуль оргструктуры: источник данных, сущности, импорт, версии, связи с обучением/аналитикой/правами. Остальные разделы не переписываются.

### 8. Исходные данные и референс
Присланный рисунок используется только как UI-референс: компактные карточки верхнего уровня, drill-down в крупные ветки, легенда цветов по типам узлов. Ни одно подразделение, уровень или должность с рисунка в данные не переносится. Для первой публикации берётся приложенный файл `ШР_ЛК_ДЛЯ_Структуры-2.xlsx` — он импортируется через тот же мастер и публикуется как действующая версия вместо ранее загруженной. Дальше структура обновляется только новыми импортами ШР.

## Технические детали

- `src/components/org/OrgGraph.tsx` — расширяется: `variant` (public/internal), фокус-ветка + breadcrumbs, expand/collapse all, поиск по людям, ссылки на профиль, блок рабочих центров в `Sheet`.
- `src/components/org/OrgStructureViewer.tsx` — переключается с `OrgChart` на `OrgGraph`, панель экспорта дополняется SVG и передачей текущего состояния (focusKey + expanded) в PNG/печатный роут `/org/print`.
- `src/components/org/OrgChart.tsx` — остаётся только как источник табличных режимов либо удаляется, если после перевода станет неиспользуемым.
- `src/lib/org.server.ts` — дополнительные правила валидации (дубли, циклы, сироты, сотрудники без должности) в существующем массиве issues; формат отчёта не меняется.
- `src/lib/org.functions.ts` / `public.functions.ts` — расширение выдачи связей рабочих центров и id профилей сотрудников для внутреннего варианта; публичный ответ остаётся обезличенным.
- `src/routes/org.print.tsx` — принимает параметры ветки и уровня раскрытия.
- Цвета — только токены `src/styles.css`, логотип и стилистика без изменений.
