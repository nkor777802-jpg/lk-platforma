# Модуль «Организационная структура предприятия»

## Что уже есть и будет переиспользовано

- `departments` (name, code, parent_id, head_name, sort_order) — уже иерархичны, это и есть OrgUnit; новую сущность подразделений не создаём.
- `positions` (name, code, department_id, is_active) — должности; `professions` — профессии (не смешиваем).
- `profiles` (department_id, position_id, profession_id, manager_id, mentor_id, grade, hire_date, personnel_number) — сотрудники и административная подчинённость.
- `work_centers` (code, name, site, area, process) — производственная структура, используется как есть.
- Центр импорта XLSX (`src/lib/import.server.ts`, `import-schemas.ts`, `/admin/import`) и таблица `import_runs`.
- Дизайн-система: токены `src/styles.css`, `EntityManager`, `AdminTable`, карточки/бейджи/диалоги, печатный роут `onboarding.print.tsx` как образец печатной формы.
- Роли `app_role` (admin/hr/teacher/manager/employee), `has_role`/`is_staff`, Password Gate админки — новых ролей не вводим.

## Что расширяем (без дублей)

- `departments`: `unit_type` (предприятие/служба/отдел/бюро/цех/участок/группа), `manager_profile_id` (реальный руководитель вместо только текстового `head_name`), `level`/`path` для быстрых деревьев.
- `positions`: `category` (руководитель / специалист / другие служащие / рабочий — из файла), необязательная связка `profession_id`.
- Связь OrgUnit ↔ WorkCenter — отдельной таблицей связей, без слияния сущностей.

## Что добавляем нового

Новые таблицы (RLS + GRANT):

- `org_versions` — версия структуры: DRAFT / VALIDATED / SCHEDULED / ACTIVE / ARCHIVED, «действует с», автор, ссылка на исходный Excel.
- `org_snapshot_units`, `org_snapshot_positions` (штатные единицы: штат / факт / вакансии, ставка), `org_snapshot_assignments` (сотрудник ↔ штатная единица) — версионный срез структуры.
- `org_subordination` — дополнительные виды подчинённости (функциональная, проектная, наставническая) вне основного дерева.
- `org_unit_work_centers` — связь подразделение ↔ рабочий центр.
- `org_import_runs` — прогон импорта: файл, профиль маппинга, отчёт валидации, diff.
- `org_mapping_profiles` — сохранённые профили сопоставления колонок Excel.

Приватный бакет хранения исходных файлов ШР (доступ admin/hr).

## Импорт Excel (по вашему файлу ШР)

Разбор проверен на загруженном файле: 589 строк, лист «ШР 26 ЛК(растан.)».

- Иерархия закодирована отступом по колонкам A–E: чем правее непустая ячейка наименования, тем глубже уровень (АУП → служба → отдел → бюро/участок).
- Колонки: должность (специальность, профессия), категория (руководитель / специалист / другие служащие / рабочий), ФИО, дата приёма, разряд, «Количество, ед: штат / факт / вакансии».
- Строки «… ИТОГО» не создают узлов, а используются для сверки численности.
- ФИО «Вакансия» → вакантная штатная единица.
- Двухстрочная шапка и служебные строки нумерации пропускаются автоматически.

Workflow: **Upload → Auto Mapping → Column Mapping → Validation → Compare → Preview → Confirm → Publish**. Профиль маппинга сохраняется, повторная загрузка проходит автоматически. Рабочий Excel менять не требуется.

## Иерархия и валидация

Иерархия определяется отступом и блоками «ИТОГО»; недостающая подчинённость не домысливается — такие записи получают статус `REQUIRES_REVIEW`.

Проверки уровней ERROR / WARNING / INFO: обязательные поля, дубли, сотрудник без должности, должность без подразделения, подразделение без родителя, некорректная ставка (0, отрицательная, факт больше штата), отсутствующий руководитель, цикл в подчинённости, конфликтующие связи, расхождение с «ИТОГО». ERROR блокирует публикацию.

## Версии и сравнение

Каждый импорт создаёт версию DRAFT. Сравнение с ACTIVE выдаёт: ADDED / CHANGED / REMOVED, новые и закрытые вакансии, смену руководителей, переводы, изменение числа штатных единиц. Публикация только вручную, с датой начала действия (в том числе будущей). История и исходные файлы сохраняются, откат — активацией предыдущей версии без удаления. Экран «Структура по состоянию на дату».

## Org Chart

Раздел `/admin/org` получает вкладки «Оргструктура (схема)» и «Импорт штатной расстановки»; просмотр дерева в личном кабинете — во вкладке «Компания» с учётом прав.

Схема рендерится на SVG/CSS без тяжёлых зависимостей: expand/collapse, zoom/pan, fit-to-screen, fullscreen, поиск, фильтры, breadcrumbs, focus branch. По умолчанию раскрыты 2 уровня, остальное — lazy. Режимы: Оргструктура | Подразделения | Руководители | Должности | Сотрудники | Штат/Факт/Вакансии | Производственная структура.

Responsive: desktop — полная схема; tablet — компактная схема с pan/zoom; mobile — drill-down по уровням с breadcrumbs и поиском.

## Экспорт

- PDF и изображение — через печатный роут `/org/print` в фирменном стиле (логотип, заголовок «ОРГАНИЗАЦИОННАЯ СТРУКТУРА / АО «Людиновокабель» / по состоянию на [дата]»), без элементов интерфейса; настройки ориентации и полей как в готовой печати адаптационного плана. SVG — из того же макета.
- Excel — плоская выгрузка, пригодная для повторного импорта.
- Область: вся структура / выбранная ветка / только подразделения / руководители / штатная структура / штатная расстановка / вакансии. Флаги: сотрудники, штат-факт, вакансии, дата.

## Права и приватность

- admin, hr — импорт, валидация, публикация, откат, полные данные.
- manager — своя ветка с сотрудниками.
- teacher, employee — структура и должности, без персональных данных (дата приёма, табельный номер, ставки скрыты).
- Все запросы через серверные функции с проверкой роли; RLS на всех новых таблицах.

## Затрагиваемые модули

`/admin/org` (новые вкладки), `/admin/import` (новый вид импорта), `/admin/production` (связь с рабочими центрами), «Компания» и профиль в ЛК, аналитика (разрезы по подразделениям). Существующая логика не переписывается.

## Риски

- Файл ШР ведётся вручную: опечатки в наименованиях («Секритариат», лишние пробелы) — нормализация и статус REQUIRES_REVIEW, без автоисправления иерархии.
- Сопоставление ФИО с существующими профилями неоднозначно (однофамильцы) — сначала по табельному номеру, иначе ручное подтверждение.
- Большая структура (≈590 строк) — lazy rendering и focus mode.
- Синхронизация опубликованной версии с рабочими таблицами не должна ломать текущие назначения — переносы мягкие, без удаления записей.

## Этапы

1. Миграция: версии, снимки, профили маппинга, связи, расширение departments/positions.
2. Серверный парсер XLSX: auto mapping, валидация, diff.
3. Админ-UI: мастер импорта из шести шагов и управление версиями.
4. Org Chart (desktop / tablet / mobile) с режимами и фильтрами.
5. Экспорт PDF / изображение / Excel.
6. Интеграция с ЛК, аналитикой и правами; проверка на реальном файле.
