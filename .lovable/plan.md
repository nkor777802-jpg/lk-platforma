# Система автотестов пользовательских маршрутов

Цель: автоматически проверять, что все страницы платформы открываются, защищённые разделы требуют входа, а публичные — доступны всем.

## Что будет сделано

### 1. Тестовый движок
Подключается Vitest (запуск командой `bunx vitest run`). Тесты живут в папке `tests/`.

### 2. Единый реестр маршрутов
Файл `tests/routes.manifest.ts` — список всех маршрутов приложения с указанием:
- публичный / требует входа / только админ;
- ожидаемое поведение (200, редирект на `/auth`);
- для динамических путей (`/test/$professionId`, `/results/$attemptId`, `/learning/$courseId`, `/professions/$slug`) — тестовые значения.

Отдельный тест сверяет реестр с `src/routeTree.gen.ts`: если добавят новый маршрут и забудут внести его в реестр — тест падает. Это гарантирует, что покрытие не устаревает.

### 3. Smoke-тесты HTTP (SSR)
Для каждого маршрута выполняется запрос к работающему приложению и проверяется:
- публичные страницы (`/`, `/about`, `/training`, `/training/professions`, `/management`, `/contacts`, `/faq`, `/privacy`, `/consent`, `/auth`, `/sitemap.xml`) отвечают успешно и содержат ожидаемый заголовок;
- страницы личного кабинета и админки без входа уводят на `/auth`, а не показывают данные;
- нет серверных ошибок 500 и пустых страниц.

### 4. Браузерные E2E-тесты (Playwright)
Сценарии в `tests/e2e/`:
- обход всех публичных страниц: страница отрисовалась, нет ошибок в консоли, работает шапка/подвал, нет битых внутренних ссылок;
- вход под сотрудником (тестовый пользователь) и обход разделов ЛК: Дашборд, Моё обучение, Тесты, История, Развитие, Сертификаты, Профиль, Я Новичок, Геймификация, Библиотека, Продукция, Компания, Видео;
- вход под администратором + ввод пароля админ-панели, обход всех 20 разделов `/admin/*`;
- проверка ключевых действий: открытие теста, отправка формы обратной связи, скачивание плана адаптации (страница печати открывается).

### 5. Отчёт
- Итог в консоли: таблица «маршрут → статус → время ответа»;
- HTML-отчёт Playwright и скриншоты упавших шагов в `test-results/`.

### 6. Страница диагностики в админке (опционально, входит в объём)
`/admin/diagnostics` — кнопка «Проверить маршруты»: серверная функция проходит по реестру маршрутов, возвращает статусы, страница показывает зелёный/красный список. Доступ только для роли admin. Это даёт быструю проверку «здоровья» сайта без запуска CLI.

## Технические детали
- Vitest + `@vitest/ui`, Playwright (браузер уже установлен в среде).
- Базовый URL берётся из переменной окружения, по умолчанию `http://localhost:8080`.
- Учётные данные тестовых пользователей — из переменных окружения, в код не попадают.
- Существующий код приложения не переписывается; добавляются только файлы тестов, конфиги и один новый роут админки.

## Что нужно от вас
Логин/пароль тестового сотрудника (не админа) для E2E-сценариев ЛК — либо тесты создадут временного пользователя через админ-доступ.
