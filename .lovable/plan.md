# Централизованные контактные данные в админ-панели

Контакты (адрес, телефон, внутренние номера, e-mail, название подразделения, режим работы) сейчас зашиты в коде (`src/content/site.ts`). План переносит их в базу и даёт форму редактирования в админ-панели — без правки кода.

## Что появится

**Админ-панель → Настройки → вкладка «Контакты»** с полями:
- Юридическое название
- Адрес
- Телефон
- Внутренние телефоны отдела персонала
- E-mail
- Название подразделения
- Режим работы

Кнопка «Сохранить» — изменения сразу видны на публичном сайте (страница «Контакты», подвал, главная) и в личном кабинете.

Редактировать может администратор; HR и остальные роли — только просмотр текущих значений.

## Где значения подхватятся

- Страница «Контакты»
- Подвал сайта
- Публичные страницы, где выводятся адрес/телефон/подразделение
- Страница «Согласие» и «Политика», где указаны реквизиты

Если запись в базе ещё не создана или недоступна, показываются текущие значения из кода — сайт не ломается.

## Техническая часть

**Миграция:**
- Строка `contacts` в существующей таблице `site_content` (поле `data` JSONB со всеми полями), заполненная текущими значениями из `src/content/site.ts`.
- Публичное чтение: `GRANT SELECT ON public.site_content TO anon` и политика `SELECT TO anon USING (key = 'contacts')` — публичные страницы рендерятся при SSR без сессии. Существующие политики (чтение авторизованным, полный доступ админу) не меняются.

**Сервер:**
- `src/lib/public.functions.ts` → `getSiteContacts()` — публичное чтение через `createPublicSupabase()`, при ошибке/отсутствии строки возвращает значения по умолчанию.
- `src/lib/admin.functions.ts` → `saveSiteContacts()` с `requireSupabaseAuth`, проверкой роли `admin`, валидацией Zod и записью в `audit_log`.

**Клиент:**
- `src/content/site.ts` — `company` остаётся как объект значений по умолчанию плюс тип `CompanyContacts`.
- `src/lib/public-queries.ts` — `siteContactsQuery` (`queryOptions`), префетч в лоадере `src/routes/_public/route.tsx`; компоненты читают через `useQuery` с `initialData` из значений по умолчанию.
- Обновляются потребители: `PublicFooter.tsx`, `_public/contacts.tsx`, `_public/index.tsx`, `_public/about.tsx`, `_public/privacy.tsx`, `_public/consent.tsx`.
- Новая вкладка «Контакты» в `src/routes/_authenticated/admin/settings.tsx` (форма на существующих shadcn-компонентах, без новой стилистики); текущий редактор ключей платформы остаётся отдельной вкладкой.

## Порядок работ

1. Миграция: строка `contacts` в `site_content` + анонимное чтение.
2. Серверные функции чтения и сохранения.
3. Query-слой и подключение к публичным компонентам с fallback.
4. Вкладка «Контакты» в настройках админ-панели.
