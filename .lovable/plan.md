# Единый файл штатной расстановки: экспорт → правка → импорт

Сейчас импорт и экспорт живут отдельно: мастер импорта разбирает исходный файл ШР со «ступенчатыми» колонками подразделений, а выгрузки (`Оргструктура`, `Штатная расстановка`, `Руководители`) дают плоские листы, которые обратно не загрузить. Цель — один канонический формат XLSX, который выгружается из системы, редактируется в Excel и загружается обратно без потери связей.

## Формат файла (лист «Штатная расстановка»)

Одна строка = одна штатная единица (позиция или конкретный человек).

| Колонка | Назначение |
|---|---|
| Уровень 1 … Уровень 5 | Иерархия подразделений (ступенчато, как в исходной ШР) |
| Код подразделения | Код из ШР, ключ связи |
| Тип подразделения | департамент / служба / отдел / участок |
| Руководитель подразделения | ФИО руководителя (заполняется в строке-заголовке подразделения) |
| Должность | Наименование должности |
| Категория персонала | руководители / специалисты / рабочие |
| ФИО | Пусто или «Вакансия», если единица свободна |
| Дата приёма, Разряд | Данные назначения |
| Штат, Факт, Вакансии | Численность |
| Рабочий центр | Код производственного участка (связь с `work_centers`) |

Дополнительные листы:
- «Справочник подразделений» — путь, код, тип, руководитель, итоги численности (только для чтения/сверки);
- «Рабочие центры» — коды и названия участков для выпадающих значений;
- «Инструкция» — правила заполнения, обязательные поля, что нельзя менять.

## Экспорт

- Новый режим выгрузки «Полная ШР (для импорта)» в панели версий/экспорта, рядом с существующими.
- Формирует файл ровно в формате выше по выбранной версии и ветке; ФИО включаются по текущему правилу доступа (админ/HR).
- Имя файла: `ШР_Людиновокабель_<версия>_<дата>.xlsx`.
- Отдельная кнопка «Скачать пустой шаблон» — тот же формат с 3–4 строками-примерами и листом «Инструкция».

## Импорт

- Авто-сопоставление колонок расширяется: распознаются заголовки «Уровень N», «Код подразделения», «Тип подразделения», «Руководитель подразделения», «Рабочий центр» — файл, выгруженный системой, подхватывается без ручного маппинга.
- Парсер дополнительно читает тип подразделения, ФИО руководителя и код рабочего центра и переносит их в срез версии и в привязки участков.
- Валидация: неизвестный код рабочего центра, нарушенная иерархия (уровень N без родителя N−1), несовпадение «Штат ≠ Факт + Вакансии», дубли должностей — предупреждения/ошибки в существующем шаге «Валидация».
- Шаг «Сравнение» продолжает показывать разницу с действующей версией; публикация — как сейчас, через черновик.

## Технические детали

- Общее описание формата вынести в `src/lib/staffing-format.ts` (список колонок, синонимы заголовков) и использовать и в экспорте, и в авто-сопоставлении.
- Экспорт: новый scope `roundtrip` в `exportExcel` (`src/lib/org-versions.server.ts`) + шаблон в том же модуле; серверная функция `exportOrgExcel` в `src/lib/org.functions.ts` расширяется новым значением scope, доступ по-прежнему только `admin` и `hr`.
- Импорт: `autoMapping` и `parseStaffing` в `src/lib/org.server.ts` дополняются колонками типа, руководителя и рабочего центра; привязка участков пишется в `org_unit_work_centers`.
- UI: кнопки выгрузки и шаблона в `OrgVersionsPanel.tsx` / `OrgImportWizard.tsx`; изменений схемы БД не требуется.
