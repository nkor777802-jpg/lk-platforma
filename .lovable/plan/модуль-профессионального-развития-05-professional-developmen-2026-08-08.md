# Модуль профессионального развития (05_Professional_Development)

Существующие части (публичный сайт, кабинет, тестирование, админка, дизайн-система) не переделываются. Модуль добавляется поверх текущей структуры и расширяет раздел «Развитие».

## Что появится

**Для сотрудника — раздел «Развитие» (`/development`)**
1. Текущая квалификация: профессия, разряд, подразделение, должность.
2. Карьерный маршрут: следующий разряд, смежные профессии, руководящая роль — визуальная цепочка уровней с отметкой достигнутых.
3. Матрица компетенций уровня: знания, навыки, требования безопасности, технологические операции, обязательные курсы и контрольные тесты — с отметкой «подтверждено / не подтверждено».
4. Индивидуальный план развития: цель, обязательные и дополнительные курсы, практические задания, тесты, сроки, ответственный, статус по каждому пункту.
5. Рекомендации системы: следующий курс, повторение темы, подготовка к квалификационному тесту (подсказка, а не решение о переводе).
6. История: завершённые этапы, аттестации и достижения — сохраняются неизменно.

**Для HR / руководителя — админ-раздел «Развитие» (`/admin/development`)**
- Справочник уровней квалификации по профессиям и переходов между ними.
- Редактор матрицы компетенций уровня.
- Ведение индивидуальных планов сотрудников: пункты, сроки, ответственные, смена статуса, подтверждение перехода на следующий разряд.
- Аналитика: сколько сотрудников развиваются, по каким профессиям, текущий этап, просроченные планы, квалификационные переходы.

## Статусы

Пункт плана и этап развития: не начато, в процессе, ожидает оценки, выполнено, требуется повторное обучение.
Переход на новый уровень фиксирует только уполномоченный (HR/админ) и он записывается в историю; изменение будущего плана не меняет уже завершённые записи.

## Связь с тестированием

Пункт плана типа «тест» закрывается автоматически при успешной попытке по привязанной профессии/тесту; провал формирует рекомендацию «повторное обучение». Пересчёт выполняется на сервере при завершении попытки.

## Техническая часть

**Миграция БД (только новые таблицы, существующие не меняются):**
- `qualification_levels` — профессия, код разряда/уровня, название, порядок, следующий уровень.
- `competencies` — привязка к уровню: тип (знание/навык/безопасность/операция), текст, обязательный курс, контрольный тест.
- `development_plans` — сотрудник, цель, профессия, целевой уровень, ответственный, срок, статус.
- `development_plan_items` — пункт плана: тип (курс/материал/практика/тест), ссылка на сущность, срок, ответственный, статус, комментарий.
- `qualification_history` — завершённые переходы: сотрудник, с уровня → на уровень, основание (попытка/решение), кто подтвердил, дата; для сотрудника только чтение.

Для каждой таблицы: GRANT, RLS (сотрудник видит своё, manager — подчинённых через `manages_user`, hr/admin — всё; запись — hr/admin/teacher), триггер `updated_at`.

**Сервер:** `src/lib/development.functions.ts` + `development.server.ts` с `requireSupabaseAuth`: создание и обновление планов и пунктов, смена статуса, подтверждение перехода уровня, генерация рекомендаций, запись в `audit_log`. Автозакрытие тест-пунктов встраивается в существующий `finalizeAttempt` в `test-engine.server.ts` без изменения его контракта.

**Данные:** `src/lib/development-queries.ts` с `queryOptions` и инвалидацией после мутаций.

**Маршруты:** переработка `src/routes/_authenticated/development.tsx` (вкладки: маршрут, план, компетенции, история) и новый `src/routes/_authenticated/admin/development.tsx` + пункт в `ADMIN_NAV`.

**UI:** только существующие shadcn-компоненты, токены дизайн-системы и `src/components/states.tsx`; для админского CRUD переиспользуются `AdminTable` / `EntityManager`.

## Порядок работ

1. Миграция БД (уровни, компетенции, планы, пункты, история).
2. Серверные функции, права, аудит, рекомендации, связь с тестами.
3. Админ-раздел «Развитие» и аналитика.
4. Переработка страницы «Развитие» для сотрудника.
