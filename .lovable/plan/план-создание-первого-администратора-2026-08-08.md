# План: создание первого администратора

## Проблема
В системе нет предустановленного администратора. При регистрации через `/auth` каждому пользователю автоматически присваивается роль `employee`, а назначение ролей защищено RLS: записывать в `user_roles` может только существующий `admin`. Без первого администратора админ-панель `/admin` недоступна.

## Решение
Добавить безопасный одноразовый механизм «bootstrap» — первый вошедший пользователь может самостоятельно стать администратором, но только пока в системе ещё нет ни одного `admin`.

## Что будет сделано

1. **Серверная функция `bootstrapFirstAdmin`**
   - Проверяет, что вызывающий авторизован (`requireSupabaseAuth`).
   - Проверяет, что в `public.user_roles` отсутствует запись с ролью `admin`.
   - Если админов нет — через `supabaseAdmin` добавляет вызывающему роль `admin`.
   - Фиксирует действие в `public.audit_log`.
   - Возвращает `{ success: true }` или ошибку, если админ уже существует.

2. **Страница `/bootstrap`**
   - Публичный маршрут (не требует роли).
   - Показывает кнопку «Стать первым администратором», если пользователь вошёл и админов ещё нет.
   - После успешного bootstrap перенаправляет на `/admin`.
   - Если админ уже есть — показывает сообщение и ссылку на `/admin` или `/auth`.

3. **Проверка и инструкция**
   - После реализации протестировать: зарегистрировать пользователя, открыть `/bootstrap`, нажать кнопку, убедиться, что `/admin` открывается.
   - Повторный вызов bootstrap должен возвращать отказ.

## Безопасность
- Механизм работает только при отсутствии администраторов.
- Требует живой сессии, поэтому назначается конкретный человек, а не аноним.
- Не оставляет постоянного бэкдора: после появления первого админа функция отключается.
- Дальнейшее управление ролями происходит через админ-панель (`/admin/users`).

## После выполнения
Пользователь сможет:
1. Зарегистрироваться или войти через `/auth`.
2. Открыть `/bootstrap` и стать администратором.
3. Перейти в `/admin` для управления платформой.
