# Публичная страница «Руководство»

## Что делаем

Раздел «Руководство» переносим из личного кабинета на открытую страницу сайта по адресу `/management`. Управление составом и фото остаётся там же, где сейчас: Админ-панель → Оргструктура → вкладка «Руководство».

## Страница `/management`

- Синий фирменный hero с заголовком «Руководство» и коротким описанием.
- Сетка карточек: фото, ФИО, должность, краткая биография. Если фото нет — заглушка с инициалами.
- Сортировка по полю порядка, показываются только активные записи.
- Собственные SEO-метаданные (title, description, og:*, canonical).
- Ссылка «Руководство» добавляется в меню шапки (десктоп и мобильное) и в подвал сайта.

## Личный кабинет

- Из страницы «О компании» (`/company`) убираем вкладку «Руководство» и связанный код карточек. Остальные вкладки (история, структура, ценности) не трогаем.

## Доступ к данным (технически)

- Таблица `management` сейчас читается только авторизованными. Добавляем миграцией политику чтения активных записей для анонимных посетителей + соответствующий GRANT.
- Бакет с фото приватный, публичные бакеты запрещены политикой воркспейса. Поэтому создаём серверную функцию `listPublicManagement` (публичный клиент, без авторизации), которая возвращает записи вместе с временными подписанными ссылками на фото, сгенерированными на сервере. Для этого добавляем политику чтения объектов бакета `management` для анонимной роли.
- Данные подгружаются через TanStack Query (`publicManagementQuery`) с префетчем в загрузчике маршрута, чтобы страница корректно рендерилась на сервере.

## Файлы

- Новый: `src/routes/_public/management.tsx`
- Новый: `src/components/public/ManagementCard.tsx`

- Миграция БД: политика чтения `management` и объектов бакета для анонимных.

## Проверка

- Открыть `/management` без авторизации: карточки и фото отображаются.
- В `/company` вкладки «Руководство» больше нет.
- Добавление руководителя с фото в `/admin/org` сразу видно на публичной странице.
