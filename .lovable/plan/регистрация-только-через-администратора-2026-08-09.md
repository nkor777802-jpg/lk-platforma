# Регистрация только через администратора

## Почему письма не приходят

В проекте не настроен домен отправки. Письма подтверждения уходят через служебный отправитель по умолчанию, поэтому часто не доходят: попадают в спам или отбрасываются почтовым сервисом. В журнале доставки за последние 14 дней нет ни одного события.

Раз регистрация будет только через администратора, письма подтверждения больше не нужны.

## Что будет сделано

1. **Отключить самостоятельную регистрацию**
   - В настройках входа запрещаются публичные регистрации.
   - Новые сотрудники заводятся только из админ-панели.

2. **Убрать вкладку «Регистрация» на странице входа `/auth`**
   - Остаётся только форма входа (e-mail + пароль) и вход через Google.
   - Внизу — подсказка: «Учётную запись создаёт отдел персонала. Обратитесь к администратору».
   - Логотип, стиль и брендинг страницы не меняются.

3. **Создание пользователей администратором**
   - Раздел `/admin/users` уже создаёт сотрудника с e-mail, паролем и ролями; аккаунт активен сразу, письмо не отправляется.
   - После создания показывается напоминание передать сотруднику логин и пароль.

4. **Проверка**
   - На `/auth` вкладки «Регистрация» нет, вход работает.
   - Попытка самостоятельной регистрации отклоняется на стороне сервера.
   - Созданный админом сотрудник входит сразу, без подтверждения почты.

## Технические детали

- Настройки авторизации: `disable_signup: true`, `auto_confirm_email: true` (чтобы созданные админом аккаунты были активны сразу).
- Файл `src/routes/auth.tsx`: удаляются `Tabs`, форма `signUp`, схема `signUpSchema` и состояние `emailSent`; остаётся форма входа и Google.
- Серверная функция `createAdminUser` уже создаёт пользователя через Auth Admin API — изменений в логике ролей не требуется.
- Восстановление пароля по почте работать не будет: пароль сбрасывает администратор. Позже можно подключить собственный домен отправки и вернуть письма.
